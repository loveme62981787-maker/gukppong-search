# 협업 기록: 화제·수집 영상의 쇼츠 처리와 길이 필터 (2026-10-15)

참여: Claude Code(`web/index.html` 담당), Codex(읽기 전용 검토). 토론 2라운드. 데이터 계약·Codex 담당 파일 변경 없음.

## 쟁점
화제 영상(`web/viral.js` 400개)에 180초 이하 쇼츠가 16개 섞여 있다(조회수 상위: 공식 홍보 필름 1:25 5,886만, 남북 도로 연결 0:51 2,372만, 외국인 반응 사례 1:57 619만 등). 사용자는 "롱폼 위주"를 요청했고 소재 등급은 181초 이상만 부여하도록 이미 합의·구현됨. 그러나 숏폼 레퍼런스가 필요할 수 있어 지우지는 않는다.

## 선택지와 결론
- A 수집 단계에서 쇼츠 제외 — 참고 자료가 사라져 기각.
- B 길이 칩 추가만 — 기본 목록에 숏폼이 섞여 기각.
- **C 채택(Codex 수정 반영)**: 기본 목록에서 숏폼을 빼되 지우지는 않고, 길이 필터로 볼 수 있게 한다.

## 합의한 규칙
1. **길이 판정은 항상 `duration_sec`**: `null`=미확인, `< 181`=숏폼, `≥ 181`=롱폼. 181초는 사이트의 분류 기준이며 `discover.ini` 의 `longform_min_sec` 기본값과 같다. `is_short` 에는 의존하지 않는다(길이 기준과 충돌하면 길이가 우선).
2. **길이 필터는 단일 선택**(복수 선택 칩이 아님): 기본(숏폼 제외) / 전체 / 롱폼만 / 숏폼만 / 길이 미확인만. **기본은 롱폼 + 길이 미확인**이다(미확인을 숨기면 수집기가 길이를 채우기 전의 영상이 사라진다).
3. **기본 모드의 예외**: 내 작업 필터(저장·메모·사용 완료·숨김)를 하나라도 선택하면 길이 제한을 적용하지 않는다. 길이를 명시적으로 고르면 그 선택이 우선한다. '새로 들어온'은 예외가 아니다.
4. **숨은 조건 표시**: 기본 모드에서는 결과 줄에 "숏폼 N개 제외 중"과 전체 보기 링크를 둔다. N은 **다른 조건을 통과한 영상 중 길이 때문에 빠진 수**이며, 내 작업 필터로 제한이 풀렸다면 문구를 표시하지 않는다. 길이를 기본이 아닌 값으로 바꾸면 요약에 제거 가능한 칩이 생기고 '전체 초기화'는 길이도 기본으로 되돌린다.
5. **0건 안내는 실제 충돌일 때만**: 길이=숏폼 + 등급·유형 선택(숏폼은 등급을 받지 않음), 길이=미확인만 + S/A/B·유형 선택(미확인은 등급 판정 전). 등급 칩의 '길이 확인 필요'는 미확인과 충돌하지 않는다. [길이 조건 해제]는 **전체**로 전환하며 결과가 생긴다고 약속하지 않는다.
6. **길이 정규화 통일**: 모든 병합 경로(화제·체험·일본 주제·글로벌)에서 유효한 `duration_sec`(유한한 0 이상 숫자) 우선, 없으면 `length` 문자열 파싱, 둘 다 없으면 `null`. 문자열은 초와 일치하면 보존하고 없거나 어긋나면 초에서 생성한다. 유효한 기존 값을 `null` 로 덮지 않는다. (기존 병합부는 `length` 문자열만 파싱해 `duration_sec` 만 있는 자료를 미확인으로 덮는 문제가 있었다.)
7. 카드 배지의 '숏폼' 표시는 길이 기준(181초 미만)이다.
