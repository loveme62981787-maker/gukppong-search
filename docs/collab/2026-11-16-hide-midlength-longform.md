## 구현
- `prepare_pages.py` (신규, 표준 라이브러리): `web/` → `_site/` 복사 후 `window.NAME=[...];` 순수 JSON 배열에서 영상을 **ID 단위**로 제거. `index.html` 의 `absorb` 순서(VIDEOS→VIRAL→…→CC_VIDEOS, 같은 변수는 `<script>` 순서)로 ID별 최종 유효 길이를 흉내 내, 최종 항목이 모두 181~600초인 ID 는 모든 배열의 사본(길이 누락·미확인 포함)을 지운다. 최종 항목 중 범위 밖/미확인이 하나라도 있으면(UI 에 남는 경우, 예: VIDEOS 안 같은 ID 300초+900초) 아무 사본도 건드리지 않아 UI 와 같게 보존하고 보고서 `conflict_preserved_ids` 에 남긴다.
  - 길이 해석은 `index.html` `normLen` 과 같음(유효 `duration_sec` 우선, 없으면 `length` 문자열). 
  - 남는 레코드·다른 구문(점수 객체, 실행 코드)은 원문 글자 그대로. 비배열 값(`SCORES`, `*_TOPICS` 등)·점수·라이선스 파일은 길이 필드가 없거나 비배열이라 영향 없음. `web/channels/` 하위 페이지는 복사만.
  - JSON 으로 읽히지 않는 배열은 건드리지 않고 보고서 `skipped_vars` 에 기록(fail-safe). 출력 폴더가 원본과 겹치거나 표식 없는 기존 폴더면 중단.
  - `--dry-run --report 파일.json` 으로 제거 ID 전체·용량 보고서 생성.
- 5개 Pages 워크플로(`update`, `hot_shorts`, `longform`, `license`, `sync-alerts`): `upload-pages-artifact` 직전에 `python prepare_pages.py --src web --out _site`, artifact 경로 `web` → `_site`. 기존 `if` 조건 유지. `.gitignore` 에 `_site/` 추가.
- `web/index.html`: 병합·길이 정규화 직후 181~600초 레코드를 `V` 에서 제거(로컬·우회 유입 방지). 이후 모든 카운트가 `V` 기준이라 목록·칩 숫자가 일치. 저장·메모·사용 완료·숨김(localStorage)은 건드리지 않음(해당 영상이 화면에서 안 보일 뿐 상태는 남음). 길이 필터 문구 `롱폼만 (10분 초과)`, 툴팁·등급 안내 문구 정정.
- 데이터 파일(`web/*.js`)·`site_store.json` 등 저장소 원본은 수정하지 않음.
