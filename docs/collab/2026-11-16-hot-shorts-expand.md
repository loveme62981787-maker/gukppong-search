# 터진 쇼츠 채널 확장 (2026-11-16)

공식 YouTube Data API(키는 출력·저장하지 않음)와 공개 데이터만 썼다. 브라우저·GUI 조작, 유료 서비스 설정, git commit/push 는 하지 않았다.

## 변경 (hot_shorts_watch.py / web/hot_shorts_view.js / workflow)
- 입장 조건: 조회수 **1만 이상**(KR·JP·TW 공통). 구독자 배수·중앙값 배수는 표시·정렬 보조로만 남기고 입장 조건에서 제거 (`min_sub_multiple`, `min_median_multiple`, `min_abs_views` 삭제).
- 채널당 12개 제한(`max_per_channel`) 제거. 읽는 범위: 최근 업로드 50 → **200**(`fetch_n`), 추가로 공식 API 의 채널 **Shorts 전용 재생목록(UUSH…)** 최대 300(`shorts_n`). 재생목록에 있으면 Shorts 확인 신호(`shorts_tab` 로 기록), 없다는 것은 증거로 보지 않는다(첫 페이지 미노출은 unknown 유지). 쿼터: 페이지당 1유닛이라 채널당 수십 유닛.
- 읽은 범위에서 밀려난 기존 확인 영상은 개수 제한 없이 누적 보존. 제외목록(`hot_shorts_exclusions.json`)·ID 기반 숨김/사용 완료/메모(`favs/done/hidden/memos`)는 그대로 공유.
- 저장 안전: `write_atomic`(임시 파일 → `os.replace`), 저장분이 잘못된 JSON 이면 `StoreCorrupt` 로 중단하고 덮어쓰지 않음(종료 코드 1). 탭·재생목록 실패는 stderr 에 경고, 기존 확인 결과 보존.
- 필드: 시드 `name_ko`(JP·TW 한국어 병기), `topic_evidence`(실제 영상 제목 근거). 화면은 `원어명 (한국어명)` 으로 표시, 검색도 name_ko 포함. KR 은 기존대로 handle 우선.
- 화면: 나라별 60개씩 그리고 `더 보기` (표시 한도일 뿐 수집 한도 아님). 기준 문구는 새 criteria 에서 생성.
- 발굴(`--discover`): TW 쿼리 16개로 확대, 기존 후보·시드는 재검증 없이 재사용, 결과는 `hot_shorts_candidates.json` 에만 저장하고 `auto_public: false`. **후보는 사람이 영상 제목을 확인해 시드에 올리기 전에는 공개되지 않는다.**
- 워크플로: cron 을 6시간 간격(`20 */6 * * *`)으로. 기존 `YOUTUBE_API_KEY` Secret 사용, 실패해도 기존 저장분으로 화면 파일 재생성·배포 계속.

## 채널 주제 근거
채널 소개가 아니라 실제 Shorts 영상 제목으로 판단했다(시드의 `topic_evidence` 에 제목 2개 저장). 포함: 외국인(미국·영국·일본·한국인 등)이 대만/한국/일본을 여행·체험·반응하는 제목이 반복되는 채널. 제외: 일반 잡학·뷰티·일상·종교음악·언어교육·국제커플 일상·뉴스(예: @짧지식, @笑ンク, @kevinsenglishroom, @jianna2, @肌肉山山, @89isme, @udn-video). 판단이 애매한 채널은 제외했다.
참고 편집·재구성 채널은 `kind=reaction_edit`/`unverified` 로 표시되며 원본이나 CC 재사용 가능으로 보지 않는다(`@hello1stkorea` 는 TV 프로그램 클립으로 보여 특히 재사용 금지). `@世界讚台灣`(사용자 본인 채널)은 목록에서 제외했다.

## 한계 / 잔여 작업
- **TW 일부 채널은 구독자 수십~수백 명 규모**(예: @happy-day-2026 59명)로, 쇼츠 중심·원본 여부가 검증되지 않았다. `unverified`/`reaction_edit` 표시만 믿고 재사용하지 말 것.
- 대만 쪽에는 `@lianxinfanyin` 유사 구성(AI 내레이션형 "英國媽…爆哭") 채널이 다수 섞여 있다. 실제 외국인 출연 영상인지 개별 확인이 필요하다.
- 1만 기준으로 모든 쇼츠를 허용했으므로 화면 개수가 크다(`web/hot_shorts.js` 약 3.7MB, store 5.5MB). 로딩이 무거우면 영상별 필드 축소·분할이 필요하다.
- Shorts 탭 *추가 페이지*(innertube continuation)는 구현하지 않았다. 대신 공식 UUSH 재생목록으로 확장했다. 재생목록이 비는 채널(예: 일부 JP)은 표본 `보류`가 많아 `쇼츠 중심` 판정이 낮게 나온다(@samuraiflag 5/20 등).
- 기존 JP·KR 시드 28개에는 `name_ko`(한국어 병기명)가 비어 있다. 신규 JP 6개·TW 35개만 채웠고, 한국어 병기명은 직접 번역한 것이라 공식 표기가 아닐 수 있다.
- `--discover` 는 키 쿼터(쿼리당 100유닛)와 시간(채널 검증이 순차라 수 분 이상)이 커서 이번에는 전량 완주하지 못했다(중단). 대신 TW 검색 결과에서 제목만 읽는 경량 경로로 후보를 골랐다. Actions 에서는 discover 를 돌리지 않는다.
- 6시간 주기 워크플로는 GitHub 에서 실제 실행해 보지 못했다(로컬 수집만 검증). 시드 76채널 순차 수집에 로컬에서 약 10분+ 걸렸고 Actions `timeout-minutes: 20` 안에 들어가는지 확인이 필요하다.
- 테스트: `python -m unittest tests.test_hot_shorts` 42개 통과, `node --test tests/test_hot_shorts_view.mjs` 13개 통과.

## 후속 수정 (코드검토 반영)
- **과거 Shorts 이어받기(backfill)**: 실행마다 ① 최신 head(업로드 `fetch_n`=200, Shorts 재생목록 `shorts_n`=300)를 다시 읽어 새 영상·조회수를 갱신하고 ② 채널별 `backfill` 커서(`token`/`pages`/`done`/`done_at`)로 Shorts 재생목록(UUSH…) 과거 구간을 `backfill_pages`=4페이지(200개)씩 이어받는다(채널당 약 8유닛, 76채널 약 600유닛/실행). 커서가 없으면 head 가 끝난 지점부터 시작한다. 끝까지 읽으면 `done`, `backfill_reset_days`=14일 뒤 커서를 비우고 다시 훑는다(조회수 갱신·삭제 보정). head 읽기나 이번 페이지 상세 조회가 실패하면 커서는 움직이지 않고 기존 영상은 그대로 보존한다. 커서는 `hot_shorts_store.json` 에만 있고 화면 파일에는 내보내지 않는다.
- **백필 한계**: Shorts 재생목록(UUSH…)이 비어 있는 채널은 과거 구간을 이어받을 수 없다(탭 첫 페이지만 확인 가능). 재생목록 토큰은 오프셋 기반이라 새 영상이 쌓이면 구간이 조금 겹치거나 삭제 시 몇 개 건너뛸 수 있고, 14일 재훑기로 보정한다. 6시간마다 도는 워크플로에서 모든 채널이 완주하기까지는 채널의 Shorts 수에 따라 수일 걸릴 수 있다.
- **혼합 주제 채널 필터**: 기본값은 엄격 필터다. 영상 제목에 `외국인(대상국 사람 제외한 국적 포함)` 신호와 `대상국(한국/일본/대만)` 이름이 **둘 다** 있어야 공개하고, 아니면 `topic_held` 로 세어 보류한다(수집 시와 `--export-only` 모두 같은 규칙). 시드 `topic_filter=false` 만 면제하며 현재 사용자 지정 참고 채널(`@lianxinfanyin`) 하나뿐이다. 제목 키워드만 본 것이라 영상을 실제로 시청해 확인했다는 뜻이 아니고, 제목에 키워드가 없는 정상 영상은 보류될 수 있다(거짓 음성 허용, 거짓 양성 최소화).
- **시드**: 快點TV(`UCokOmKCQAugpV1t6lombFFA`)는 `exclude=true`(iPhone 선물·할머니 매실장난·기차괴한 등 무관 영상 확인). 이번 실행에서 새로 올린 시드 42개의 `kind` 는 근거가 없어 `reaction_edit` 에서 `unverified` 로 되돌렸다. `reaction_edit`/`unverified` 모두 원본·CC 재사용 가능 표시가 아니다.
- **공개 데이터 변화**: 기존 저장분(8,784개)을 `--export-only` 로 다시 내보내면 제목 필터 후 74채널·4,241개(JP 2,490 / KR 1,059 / TW 692)로 줄고 4,505개는 보류된다. 저장분 자체는 지우지 않는다(보류는 화면에서만 숨김).
- **저장·배포 주의**: 부모가 최종 수집·배포한다. 새 데이터가 있으면 `python hot_shorts_watch.py --export-only` 만 실행하면 된다(네트워크 없음). 공개 파일에는 API 키 등 비밀을 두지 않는다.
- 참고: 6시간 주기 cron(`20 */6 * * *`), 입장 조건은 조회수 1만 이상(KR/JP/TW 공통), 채널당 표시·수집 개수 제한 없음.
