# 절약형 영상 일괄 처리 프로그램

## 현재 상태
- 기본 중지. Codex heartbeat automation-4도 PAUSED.
- Windows 예약 작업은 설치하거나 활성화하지 않았다.
- 실제 Gemini/Claude 채점과 사이트 게시를 실행하지 않았다.
- 개발 변경은 로컬 검토 상태. 생산 운영 전 코드 커밋·원격 동기화가 필요하다.

## 동작
batch_daily.py가 일반 Python으로 일괄 실행한다. Codex/OpenAI 호출은 없다.
1. 비공개 알림 저장소를 동기화하고 비공개 후보 목록을 생성한다.
2. 영상 ID 중복, 이미 채점한 영상, Claude 비교 기준, 10분 이하 또는 길이 미확인/오류를 제외한다. 한국·일본 목록을 번갈아 처리한다. 대만은 현재 채점 기준 범위 밖이다.
3. 저장된 자막을 재사용하거나 공개 YouTube 자막을 가져온다. 접근 불가·부분 자막은 보류하며 인증 우회나 브라우저 수동 작업으로 자동 전환하지 않는다.
4. Gemini 3.8 Flash Medium이 FM으로 1차 채점한다. GEMINI_BATCH_MODEL로 변경할 수 있다.
5. 인용문·시각·배점·중복을 프로그램으로 검사한다. 등급 경계 ±2점, 불확실성, 검사 실패만 Claude Sonnet이 기존 결과와 원문을 검수한다. CLAUDE_REVIEW_MODEL로 변경할 수 있다.
6. 명확한 결과는 프로그램 검사 출처로, Claude 검수 결과는 Claude 출처로 기록한다. Codex가 전수 검수했다고 표시하지 않는다.
7. 시험 결과는 비공개 파일에 저장하고 자동으로 멈춘다. 생산 모드는 검사한 결과를 모아 테스트·커밋·push한다. push 성공은 GitHub Actions 배포 완료를 뜻하지 않는다.

실패/보류도 시도 개수에 포함한다. 같은 영상은 자동 재시도하지 않는다. 모델 실패는 즉시 중단하며 다른 모델/API로 자동 우회하지 않는다. 캐시는 모델·자막·FM·요청문에 묶인다. 다른 ID로 재업로드된 동일 영상의 내용 중복은 탐지하지 않는다.

## 나중에 사용자가 20개 시험을 요청했을 때
작업 폴더에서 다음을 실행한다. 지금은 실행하지 않는다.

    python batch_score.py resume-pilot
    python batch_daily.py
    python batch_score.py status

최초 시험은 재시작·날짜 변경을 포함해 누적 최대 20개 시도다. 시험 종료 후 자동 중지하며 게시하지 않는다. 비공개 ../telegram-score-private/batch_report.json에는 시도·성공·보류 수, Gemini/Claude 호출 수, 캐시 재사용, 소요 시간을 저장한다. 클라이언트별 토큰 과금량은 보고서가 추정하지 않는다.

실제 구독 인증, 긴 자막 stdin 전달, YouTube 자동 자막 확보 성공률은 이 20개 시험에서 검증해야 한다. 모델 목록 조회는 확인했지만 실제 모델 호출은 하지 않았다. 자막 접근 제한으로 처리량이 줄 수 있으므로 하루 200개 완료를 보장하지 않는다.

## 시험 보고서 검토 후 생산 운영 승인
성공한 결과가 없거나 공통 모델 오류가 남아 있으면 전환할 수 없다. 먼저 status에 표시된 report_hash와 실제 보고서를 확인한다.

    python batch_score.py approve-production --accept-report 보고서해시

이 명령 후에도 중지 상태다. 명시적 재개 시에만:

    python batch_score.py resume-production
    python batch_daily.py

한국시간 하루 최대 200개 시도. 예약 진입점은 하루 한 번 시작하며 날짜 경계를 넘으면 해당 실행을 끝낸다. 같은 날짜 오류 후 재실행은 자동으로 채점을 더 하지 않는다. 생산 모드의 사전 검사에서 main 브랜치·깨끗한 작업 폴더·원격과 같은 커밋을 요구한다. 프로그램 코드의 검토 및 커밋/원격 동기화를 먼저 마쳐야 한다.

## 예약
install_batch_task.ps1은 필요할 때 실행하면 한국시간 매일 오후 7시의 Windows 작업을 **비활성 상태로만** 등록한다. 이 작업은 Codex 앱을 사용하지 않는다. 등록/활성화는 아직 하지 않았다. 승인된 생산 운영 이후 사용자가 요청할 때에만 Windows 작업을 활성화한다. PC가 켜져 있고 사용자 로그인이 유지돼야 실행되며, 절전·종료 중 누락된 실행은 몰아서 처리하지 않는다.

## 중지와 복구
    python batch_score.py pause

처리 중에는 score.lock을 쓰므로 이 명령은 중복 실행 오류를 낼 수 있다. 실행 중단은 해당 Python 작업을 종료한 뒤 상태를 확인한다. 강제 종료 뒤 남은 잠금 파일은 프로세스가 종료된 것을 확인하기 전 삭제하지 않는다.

실패 영상은 원인을 고친 뒤 명시적으로 다음을 실행한다. 일일/시험 누적 예산은 복원되지 않는다.

    python batch_score.py retry --id 영상ID

배포 실패 후 기존 결과만 복구:

    python batch_daily.py recover

deployment.json의 커밋·파일 해시가 맞을 때만 재시도한다. 다른 사용자 수정이나 커밋이 있으면 멈춘다. preparing 단계에서 전원이 끊긴 경우 자동 덮어쓰기를 하지 않으므로 수동으로 차이를 검토해야 한다. GitHub 동시 업데이트로 push가 거절되면 저장된 점수를 유지하고 수동 병합 후 재검토한다. 점수는 push 성공 후에만 published로 표시한다.

## 보류 판정 및 기존 사이트 후보 지원

- set-source --source all 적용 완료, enabled=false와 pilot 상태 유지.

## Gemini 인용 수정 우선 경로
인용/형식/근거누락이 발견되면 원안·정확한 검증 오류·자막·FM을 제공하여 Gemini가 최대 한 번 수정한다. 수정도 기존 disposition/validate_review로 다시 검사한다. 점수 범위, 정확 인용, 시각, 중복, 가중치, 의미 불확실성 및 등급 경계 기준은 바꾸지 않았다.
초기 semantic_uncertainty/grade_boundary는 수정으로 사라지거나 held로 바뀌어도 Claude 검수로 보낸다. 초기 점수·구체적인 불확실성과 최신 수정 결과를 함께 전달한다. 오류만 해소된 명확한 결과는 Claude를 생략한다. 공통 모델 실패는 기존 회로 차단을 유지한다.
수정 프롬프트/원안/오류를 포함한 독립 캐시를 사용한다. gemini_repair_reviews는 캐시 포함 수정 단계 수, gemini_repair_accepted는 Claude 없이 승인된 수정 수다. 실제 호출 수와 cache_hits는 기존 필드로 별도 집계한다.
독립 설계/코드 검토 반영. 전체64테스트 통과, 등급 경계 보존 추가 케이스도 통과. 추가 실모델 호출 없음. 실제 절감률은 아직 미측정. automation-4 PAUSED와 enabled=false 확인.

중단된 동일20개 시험은 일회성 resume_timeout_once.py가 기존 완료8개를 보존하고 시간초과1개+미처리11개만 이어서 처리한다. 일일 이력에 명시 재시도1회를 추가하고 기존 결과/사용량을 아카이브한다. 종료 후 비교 결과를 파일로 저장한다. 예약 작업 설치/활성화 및 새 시험 결과 게시 없음. Codex 반복 폴링 없이 별도 Python 프로세스로 실행한다.

## JSON 오류 수정과 자동채점 재개 승인
이미 통과한 4개 게시를 사용자가 승인했고, JSON 오류를 수정한 뒤 자동채점 재개를 승인했다. 문제는 호출(returncode/상태) 자체는 성공했는데 Gemini 응답 텍스트가 유효한 JSON 객체가 아닌 경우, 기존 코드가 이를 `call_model`의 공통 `ValueError` 처리로 묶어 `ModelFailure`(RuntimeError)로 올려서 회로차단(`state['enabled']=False`, `fatal=True`)을 트리거해 나머지 후보 처리를 멈췄던 것이다.
`ReviewFormatError(ValueError)`를 새로 추가해 이 경우만 분리했다: markdown 펜스 제거 후 `json.loads` 실패이거나 결과가 객체(dict)가 아니면 `ReviewFormatError`를 던진다(부분 추출·점수 복구 없음, 전체 객체만 허용). 인증/한도/빈 CLI 출력/논제로 종료/claude 구조화 출력 스키마 위반 등 기존 `ModelFailure` 경로는 그대로 두어 회로차단을 유지한다. `run_batch`의 held 처리에서 `ReviewFormatError`는 `RuntimeError`가 아니므로 기존처럼 해당 영상만 보류하고 다음 후보로 진행하며, held 이유 문자열에 원인(`invalid_review_json`/`review_not_object`)을 그대로 남긴다. `model_review`의 캐시 읽기도 동일하게 손상된 캐시 JSON을 `ReviewFormatError`로 구분해 영상별 보류로 처리하고 모델을 다시 호출하지 않는다.
타임아웃(`ModelTimeout`, 2026-10-22 앞서 추가) 처리 방식과 동일한 패턴이며 기존 240초→600초/660초 타임아웃 변경은 보존했다. 테스트 4종을 `tests/test_batch_score.py`에 추가: 성공 응답이 비JSON/비객체일 때 `ReviewFormatError`, 그 보류가 다음 영상 처리를 막지 않음, 손상된 캐시 JSON이 모델 재호출 없이 보류됨, 실제 CLI 실패(`ModelFailure`)는 여전히 회로차단한다는 회귀 검증. 커밋·상태 변경·게시는 하지 않았다.
